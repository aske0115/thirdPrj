# 인계 문서

> **최신(2026-11-17 PoC 판정)**: 쇠공 PoC를 iPhone에서 해 본 사용자 판정 **"켜자마자 재미없음"**(결정 007) → **기획 변경 중.** 쇠공 코드는 태그 `wrecker-poc`로 보존. 새 기획은 사용자가 즐겨 하는 게임을 먼저 듣고 정함(아래 "바로 할 일"). Godot 엔진·저장소 구조·봇·화면 저장·`ios.sh`는 그대로 씀.

## 바로 할 일
1. ✅ 사용자 취향·한계·목표 들음(작업 일지 「새 기획 출발점」): 스토리 RPG·서바이버 액션·방치형·짬짬이, 매출 상위가 기준, 한계는 콘텐츠 수급·디자이너 부재, 목표는 AI로 1인 수준을 넘는 제품(게임 아니어도 됨).
2. 결정 007의 교훈 4가지를 기준으로 기획 담당·디자인 담당이 새 안 → 사용자 선택.
3. 첫 10초만 만든 아주 작은 PoC → `./ios.sh`로 실기기 판단.

> **이전(2026-11-17 첫 PoC)**: Godot 4.7.2로 1스테이지 PoC가 돌아갑니다. 블록 건물이 부딪힌 자리부터 부서지고(기둥 붕괴·위층부터 주저앉기), 쇠공이 끌기로 굴러가며 커지고 달아오르고, 경찰차가 쫓아와 쏘고, 변압기를 부수면 정전 연쇄가 일어납니다. 봇·화면 저장 도구가 있습니다(`docs/SETUP.md`). 화면 `docs/screens/`. **다음: 난이도 수치 맞추기(봇이 너무 쉽게 이김) → iOS·안드로이드 내보내기 → 사용자 실기기 판단.**

## 지금 상태 한눈에
- 기획: `docs/GDD.md`(콘셉트·규칙·화풍), 결정 001~006(`docs/DECISIONS.md`). 끝부분 「재미·재방문·한 달 고리」는 **제안(사용자 확인 전)**.
- 코드(`scripts/`):
  - `main.gd` 진입점. 장면을 코드로 짓고 판 흐름·입력(누른 자리 조이스틱)·카메라·히트스톱·흔들림·진동·변압기·봇·화면 저장·통계 출력.
  - `city.gd` 블록 건물(MultiMesh 1개)·`damage_sphere`·기둥 붕괴·주저앉기·정전·파편(MultiMesh 1개, 고리 버퍼).
  - `ball.gd` 쇠공(관성·열기·굴러가는 회전·사슬 verlet·바닥 빛 고리·크기 단계).
  - `cops.gd` 경찰차(추격·사격·사이렌·서치라이트)와 주차된 차.
  - `fx.gd` 입자(먼지·유리·불꽃·폭발)·불길·그을음 데칼·소리.
  - `hud.gd` 시간·파괴율·체력·분노 버튼·조이스틱·시작/결과 창.
  - `tuning.gd` 모든 수치(난이도 담당).
  - 셰이더 `shaders/block.gdshader`(창문을 면 좌표로 그림, 전기 끊기면 꺼짐), `shaders/ball.gdshader`(녹·균열·열기).
- 확인 방법: 봇 `--bot`이 가장 가까운 건물로 달려가 박음. `STATS`(5초마다)·`RESULT`(끝) 줄로 비교.
- 에셋: Kenney CC0만, `docs/ASSETS.md`.

## 알려진 문제
- 너무 쉬움: 봇이 23초에 60% 파괴(첫 측정). 난이도 담당이 `tuning.gd`로 맞추는 중.
- 쇠공에 표정이 없음(결정 006 위험) — 균열 빛·사슬로 충분한지 실기기에서 판단.
- 사이렌 소리·건물 붕괴 전용 소리 없음(Kenney 충돌음 낮은 음으로 대신).
- 카메라가 건물 뒤의 쇠공을 가릴 때가 있음(각도를 높여 줄였지만 남음).
- 실기기 성능 미측정(파편 600·입자). 헤드리스 봇의 fps는 의미 없음.
